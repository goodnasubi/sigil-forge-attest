# sigil-forge-attest の概念と設計方針

## 位置づけ

Sigil のバックエンド系部品のひとつ。2026-11-22 に池田さんが決定した。

- **forge** ＝ 鍛冶場。物を作る場所であり、作った物に刻印を押す場所でもある。
- **attest** ＝ 証明。成果物が正しく作られたことを証し立てる。

Sigil のセキュリティ方針である ADR 0027 の、サプライチェーンの層に対応する部品になる。

## 役割

作った物に鍛冶場の刻印を押すように、ビルド成果物への署名と検証の仕組みを提供する。あわせて、依存関係の出所と完全性（ハッシュや署名の照合）をチェックする。

各リポジトリの CI と連携し、署名のない成果物や出所の不明な依存を検出して知らせる形を将来像とする。知らせる先は sigil-argus-observe の監視や、各リポジトリの Issue が考えられる。

## 今後の検討点

- 署名に使う鍵の保管方法。鍵そのものが漏れれば証明の意味が無くなるため、保管と失効の扱いを先に決める。
- 検証に失敗した成果物の扱い。止めるのか、知らせるだけにするのかは、対象の重要さによって変わるため、一律には決めない。
